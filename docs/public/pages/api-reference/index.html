Arcline API Reference

Build powerful commerce experiences with the Arcline REST API. Manage users, products, orders, and real-time webhooks with a consistent, predictable interface.

Base URL https://api.arcline.dev/v2

Authentication

Authenticate requests with API keys or Bearer tokens.

API Key Authentication

All API requests must include a valid API key in the Authorization header. You can generate keys from your Arcline Dashboard.

Authorization Header
Authorization: Bearer sk_live_••••••••••••••••
Example Request
curl https://api.arcline.dev/v2/users \ -H "Authorization: Bearer sk_live_a1b2c3d4e5f6" \ -H "Content-Type: application/json"

Users

Create, retrieve, and manage user accounts in your organization.

GET /v2/users

Returns a paginated list of all users. Results are sorted by creation date in descending order. Supports filtering by status and role.

ParameterTypeDescription
limitoptional integer Number of results per page (1–100, default 25)
statusoptional string Filter by status: active, suspended, pending
cursoroptional string Pagination cursor from previous response
Response — 200 OK
{ "object": "list", "data": [ { "id": "usr_9f8e7d6c5b4a", "object": "user", "name": "Elena Vasquez", "email": "elena@example.com", "role": "admin", "status": "active", "created_at": "2026-08-15T09:42:00Z" } ], "has_more": true, "total_count": 1284 }
POST /v2/users

Creates a new user account. An activation email is sent automatically unless skip_verification is set.

ParameterTypeDescription
namerequired string Full name of the user
emailrequired string Unique email address
roleoptional string admin, member, or viewer (default: member)
Request
POST /v2/users HTTP/1.1 Content-Type: application/json Authorization: Bearer sk_live_a1b2c3d4e5f6 { "name": "Marcus Chen", "email": "marcus@example.com", "role": "admin" }
Response — 201 Created
{ "id": "usr_3a2b1c0d9e8f", "object": "user", "name": "Marcus Chen", "email": "marcus@example.com", "role": "admin", "status": "pending", "created_at": "2026-08-30T10:15:00Z" }
PUT /v2/users/:id

Updates an existing user by ID. Only the provided fields are modified; omitted fields remain unchanged.

ParameterTypeDescription
idrequired string The user's unique identifier (path parameter)
nameoptional string Updated full name
statusoptional string active or suspended
Response — 200 OK
{ "id": "usr_9f8e7d6c5b4a", "object": "user", "name": "Elena V. (Updated)", "status": "active", "updated_at": "2026-08-30T10:20:00Z" }

Products

Manage your product catalog — items, pricing, and inventory metadata.

GET /v2/products

Lists all products with optional category filtering and full-text search. Returns pricing tiers and availability status.

ParameterTypeDescription
categoryoptional string Filter by product category slug
qoptional string Full-text search query
in_stockoptional boolean Filter to only in-stock items
Response — 200 OK
{ "object": "list", "data": [ { "id": "prod_xK9mL2nP", "object": "product", "name": "Arc Starter Kit", "description": "Complete toolkit for new developers", "price": { "amount": 4999, "currency": "usd", "interval": null }, "in_stock": true, "created_at": "2026-06-01T12:00:00Z" } ], "has_more": false }
POST /v2/products

Creates a new product in your catalog. Pricing is specified in the smallest currency unit (e.g., cents for USD).

ParameterTypeDescription
namerequired string Product display name
pricerequired object Price object with amount (integer) and currency (string)
descriptionoptional string Product description (max 500 chars)
Request Body
{ "name": "Arc Pro Plan", "description": "Full access to all Arcline features", "price": { "amount": 19900, "currency": "usd", "interval": "month" }, "category": "subscriptions" }
DELETE /v2/products/:id

Permanently deletes a product. This action is irreversible. Products with active subscriptions cannot be deleted.

Response — 200 OK
{ "id": "prod_xK9mL2nP", "object": "product", "deleted": true }

Orders

Process and track customer orders through fulfillment.

GET /v2/orders

Retrieves all orders with line items, payment status, and shipping information. Supports date-range filtering.

ParameterTypeDescription
statusoptional string pending, confirmed, shipped, delivered, cancelled
created_afteroptional string ISO 8601 timestamp — filter orders created after this date
customer_idoptional string Filter by customer user ID
Response — 200 OK
{ "object": "list", "data": [ { "id": "ord_Qp4R7sT1", "object": "order", "customer_id": "usr_9f8e7d6c5b4a", "status": "confirmed", "items": [ { "product_id": "prod_xK9mL2nP", "quantity": 2, "unit_price": 4999 } ], "total": 9998, "currency": "usd", "created_at": "2026-08-29T16:30:00Z" } ], "has_more": false }
POST /v2/orders

Creates a new order. Inventory is reserved immediately upon creation. Payment is processed asynchronously via webhook.

Request Body
{ "customer_id": "usr_9f8e7d6c5b4a", "items": [ { "product_id": "prod_xK9mL2nP", "quantity": 1 }, { "product_id": "prod_Hj3Kl8Mn", "quantity": 3 } ], "shipping_address": { "line1": "42 Quantum Lane", "city": "San Francisco", "state": "CA", "postal_code": "94102", "country": "US" } }
Response — 201 Created
{ "id": "ord_Mn2Bv5Cx", "object": "order", "status": "pending", "total": 24996, "currency": "usd", "payment_status": "awaiting", "created_at": "2026-08-30T10:25:00Z" }

Webhooks

Subscribe to real-time event notifications for your application.

GET /v2/webhooks

Returns all registered webhook endpoints for your account, including delivery status and recent failure counts.

Response — 200 OK
{ "object": "list", "data": [ { "id": "whk_Lp8Mn2Bv", "object": "webhook_endpoint", "url": "https://app.example.com/hooks/arcline", "events": [ "order.created", "order.paid", "user.created" ], "active": true, "failure_count": 0, "created_at": "2026-07-10T08:00:00Z" } ] }
POST /v2/webhooks

Registers a new webhook endpoint. Arcline will send an HTTP POST request to your URL with a JSON payload whenever a subscribed event occurs.

ParameterTypeDescription
urlrequired string The HTTPS URL to receive webhook payloads
eventsrequired string[] List of event types to subscribe to
secretoptional string Custom signing secret (auto-generated if omitted)
Request Body
{ "url": "https://app.example.com/hooks/arcline", "events": [ "order.created", "order.paid", "order.cancelled", "product.updated" ] }
DELETE /v2/webhooks/:id

Removes a webhook endpoint. Pending deliveries in the retry queue are discarded.

Response — 200 OK
{ "id": "whk_Lp8Mn2Bv", "object": "webhook_endpoint", "deleted": true }

Error Codes

Standard HTTP status codes and Arcline-specific error types.

Arcline uses conventional HTTP status codes to indicate the success or failure of an API request. Codes in the 2xx range indicate success, 4xx indicate client errors, and 5xx indicate server-side issues.

CodeStatusDescription
200 OK Request succeeded. Response body contains the result.
201 Created A new resource was successfully created.
204 No Content Request succeeded with no response body (common for deletes).
400 Bad Request The request was malformed or missing required parameters.
401 Unauthorized Missing or invalid API key / Bearer token.
403 Forbidden Authenticated but insufficient permissions for this resource.
404 Not Found The requested resource does not exist.
409 Conflict A conflicting operation is in progress (e.g., duplicate email).
422 Unprocessable Syntax is valid but semantically incorrect (e.g., negative price).
429 Rate Limited Too many requests. Retry after the Retry-After header value.
500 Server Error An unexpected internal error. Contact support if persistent.
503 Unavailable Service temporarily down for maintenance. Check status page.
Error Response Format
{ "error": { "type": "invalid_request_error", "code": "parameter_missing", "message": "The 'email' field is required.", "param": "email", "doc_url": "https://docs.arcline.dev/errors/parameter_missing" } }

Rate Limits

API request quotas and throttling behavior.

The Arcline API enforces rate limits to ensure fair usage. Limits are applied per API key and measured using a sliding window algorithm.

Free 100 requests / minute 10 requests / second
Pro 1,000 requests / minute 50 requests / second
Enterprise 10,000 requests / minute 200 requests / second
